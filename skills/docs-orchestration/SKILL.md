# Docs Orchestration

Сводный навык: многоагентный конвейер + оформление результата в документ.

## Когда использовать
Пользователь просит: «собери команду и сделай ТЗ», «запусти оркестратор и оформи отчёт», «проанализируй и сделай презентацию», «сделай спецификацию командой и сохрани в docx».

## Процесс

### Шаг 1. Запусти оркестратор
Выбери реализацию по контексту (см. навык `orchestrator`):
- **Claude Desktop**: `orchestrate_start {task, roles?, autoRetry?}` → затем `status`/`next`/`resolve` до результата.
- **Claude Code**: субагенты или `/orchestrate`.
- **DSH**: `agent_teams_*`.

Роли по умолчанию: analyst → architect → approver → developer → devops → qa.
Управляй гейтами: REJECTED → retry к analyst; FAILED → retry к developer. Автоповтор включён.

### Шаг 2. Собери итог
Из результатов ролей сформируй структурированное содержимое:
- **analyst** → требования
- **architect** → архитектура
- **developer** → что реализовано
- **qa** → статус тестов
- Плюс ключевые решения и метрики.

### Шаг 3. Оформи в документ
По формату (используй соответствующий навык):
| Формат | Навык | Когда |
|---|---|---|
| Word (.docx) | `docx` | отчёты, ТЗ, письма |
| Презентация (.pptx) | `pptx` | питчи, обзоры |
| Excel (.xlsx) | `xlsx` | таблицы, метрики, планы |
| PDF | `pdf` | финальные документы, печать |

Вызови навык (`use_skill {name: "docx"}` в Desktop, или Skill tool в Claude Code) и следуй его инструкциям для создания файла.

### Шаг 4. Отдай результат
Сообщи пользователю:
- путь к созданному файлу
- краткую сводку по ролям (что сделала каждая)
- статус гейтов (APPROVED/PASSED)

## Правила
- Не пропускай шаг оркестрации — если задача большая, сначала команда, потом документ.
- Выбирай формат по запросу пользователя; если не указан — спроси или предложи по типу (ТЗ → docx, отчёт → docx/pdf, таблица → xlsx, презентация → pptx).
- Проверь, что файл реально создан и открывается, прежде чем отчитываться.
